# pair-wise-yy-60 碳减排项目监测证据核验与签发准备平台

按监测周期完成活动数据、排放因子、证据来源、异常波动和计算链核验。记录、发现项与签发门禁挂在**同一份按版本演进的「签发依据」**上，杜绝「各存一份、核验员拿旧结论放行」。

## 核心机制（`lib/issuance/`）

- **统一签发依据**：记录、发现项、门禁共享一个 `basisVersion`；所有变更进入同一账本（`LedgerEntry`），全局操作号 `opSeq` 单调递增。
- **修订带版本 + 操作号**：每次有效修订/补证前进一个依据版本，并分配唯一 `opId`；记录同时保留修订链号 `revision`。
- **两人同时修订（乐观锁）**：修订携带加载时的 `baseVersion`；先到者生效，后到者版本过期 → 记一笔「冲突留痕」（占操作号），修订内容**不进依据**，可放弃或基于最新版本 rebase 重生。
- **数据/单位/来源一变即失效重算**：关联发现项标记失效原因并留痕（不删除），按新版本规则重算（新旧两代并存）；自动门禁在新版本立即重评并绑定新版本，人工（方法学）门禁回到「待重算」等复核员重认；已核验记录回到「复核中」，旧核验结论标记过期。
- **复核确认绑定版本**：确认时记录 `basisVersion` 并留存该版本快照；依据前进后确认自动失效，签发放行校验「确认版本 == 当前版本 且 全部门禁在当前版本通过」，旧结论直接拒绝。
- **角色门禁**：现场只能补证/发起补证，修订、关闭发现项、门禁重算、确认、放行按角色在服务端拒绝；拒绝不占操作号。
- **写入失败恢复**：从最后确认版本快照恢复，确认点之后误记的账（含冲突留痕）整段回滚，恢复本身记账；同一 `opId` 重试由引擎幂等回放，不重复记账（补证不会补两遍、修订不会记两笔）。
- **老记录补首版**：无依据版本号的历史记录在建立依据时统一补成 V1，并逐笔记「补首版」账。

## 技术栈

Next.js App Router、MUI、Zustand、ky、Zod、TypeScript。领域引擎 `lib/issuance/engine.ts` 为纯函数、可独立测试；`/api/evidence` 为进程内唯一依据实例。

## 运行

```bash
npm install
npm run dev      # http://localhost:62060
npm run build
```

## 演示路径

1. 右上角切换角色（现场 / 核验员 / 复核员），现场身份点「修订」会被拒绝。
2. 任一记录「修订」时勾选「模拟两人同时修订」：先到生效、后到在核验页出现冲突卡，可放弃或重生。
3. 勾选「模拟写入超时」：账本已落但响应丢失，顶部出现「原操作号重试（不重复记账）」与「从最后确认版本恢复」。
4. 对 ACT-0337 补证、关闭发现项，观察证据门禁按新版本重算；再修订数据，观察确认与方法学门禁过期、放行被拒。
5. 复核员在签发页「确认当前依据版本」后放行；再制造修订，旧确认无法放行。
6. 「重置演示」回到种子依据（V1）。
